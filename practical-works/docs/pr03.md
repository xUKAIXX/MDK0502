# Практическая работа № 3. Entity Framework Core и база данных

**Вариант 3:** агентство недвижимости.

**Тема:** подключение базы данных через EF Core, модель данных, конфигурация и сидирование.

**Цель:** научиться описывать сущности, связи и конфигурацию EF Core, сохранять данные в локальную базу и заполнять её начальными значениями.

> Практическая работа восстановлена по конспекту лекции K05 (в исходном комплекте отдельного файла на эту тему не было).

## Что сделано

- локальная база **SQLite** (`realestate-agency.db`), создаётся автоматически;
- `ApplicationDbContext` наследуется от `IdentityDbContext<ApplicationUser>` (готовность к практике 7);
- сущности: `Property`, `PropertyType`, `District`, `Agent`, `Deal`;
- связи «один ко многим» и «многие к одному», внешние ключи, индексы;
- конфигурации в отдельных классах `IEntityTypeConfiguration<T>`;
- конвертация `decimal` в целое число копеек для корректной сортировки в SQLite;
- сид данных: типы объектов, районы, агенты, 12 объектов, 4 сделки;
- автоматическое создание базы при первом запуске (`EnsureCreatedAsync`), при наличии миграций — `MigrateAsync`.

Ключевые файлы:

- `src/RealEstateAgency.Infrastructure/Persistence/ApplicationDbContext.cs`
- `src/RealEstateAgency.Infrastructure/Persistence/Configurations/*.cs`
- `src/RealEstateAgency.Infrastructure/Persistence/DbSeeder.cs`
- `src/RealEstateAgency.Infrastructure/DependencyInjection.cs`

## Ответы на контрольные вопросы

1. **ORM.** Object-Relational Mapping — преобразование объектов C# в строки таблиц и обратно. EF Core берёт на себя SQL, отслеживание изменений и миграции.
2. **EF Core и ручной SQL.** EF Core ускоряет разработку, типизирует запросы и поддерживает миграции; ручной SQL даёт полный контроль, но требует больше кода и внимательности.
3. **DbContext и DbSet.** `DbContext` — сеанс работы с базой и единица работы; `DbSet<T>` — типизированное представление таблицы.
4. **Первичный ключ.** По соглашению свойство `Id`, либо `[Key]`, либо `HasKey` в Fluent API.
5. **Отложенное выполнение LINQ.** Запрос строится как выражение и выполняется только при перечислении: `ToList`, `FirstOrDefault`, `Count` и т. п.
6. **`IQueryable` и `IEnumerable`.** `IQueryable` выполняется провайдером (например, SQLite), `IEnumerable` — в памяти приложения.
7. **Асинхронные методы.** Не блокируют поток на время ожидания базы, повышают пропускную способность.
8. **Миграция.** Снимок изменений модели. Создаётся `dotnet ef migrations add`, применяется `dotnet ef database update`.
9. **Регистрация DbContext.** `builder.Services.AddDbContext<ApplicationDbContext>(options => options.UseSqlite(connectionString));`.
10. **`SaveChangesAsync()`.** Сохраняет все отслеженные изменения одной транзакцией.
11. **`[Bind]`.** Ограничивает список свойств, которые связываются из запроса, защищая от over-posting.
12. **`[NotMapped]`.** Исключает свойство из схемы базы, если оно не должно храниться.
13. **Пагинация.** `Skip((page - 1) * pageSize).Take(pageSize)`.
14. **`ToList()` до `Where()`.** Все строки будут загружены в память, и фильтрация выполнится на клиенте — это медленно и лишает смысла `IQueryable`.
15. **Конфликты параллелизма.** EF Core использует concurrency token (например, `RowVersion`); при конфликте выбрасывается `DbUpdateConcurrencyException`.

## Как проверить

1. Запустите приложение — файл `realestate-agency.db` появится рядом с проектом.
2. Откройте `/Properties/Index` — должны быть предзаполненные объекты.
3. Проверьте, что после добавления объекта он сохраняется после перезапуска приложения.
