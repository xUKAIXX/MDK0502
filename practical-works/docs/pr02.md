# Практическая работа № 2. Расширение MVC: CRUD, поиск и валидация

**Вариант 3:** агентство недвижимости.

**Тема:** редактирование, удаление, поиск, сортировка, валидация и пагинация.

**Цель:** закрепить CRUD-операции, реализовать поиск и сортировку, серверную валидацию и постраничный вывод.

## Что сделано

- `Details` — карточка объекта со всеми полями;
- `Edit` — редактирование объекта с проверкой бизнес-правил;
- `Delete` — удаление с подтверждением (GET-подтверждение + POST-удаление);
- поиск по названию, адресу и агенту;
- фильтры по статусу, типу, району и диапазону цены;
- сортировка по цене, площади, году и названию;
- пагинация по 6 объектов на страницу;
- валидация через атрибуты `[Required]`, `[StringLength]`, `[Range]`;
- вывод общего количества объектов;
- отдельные действия `Delete` и `DeleteConfirmed` для защиты от удаления через GET;
- скрытое поле `Id` в форме редактирования.

## Ответы на контрольные вопросы

1. **GET и POST.** GET получает данные, параметры передаются в URL, запрос можно закэшировать и добавить в закладки; он не должен менять состояние. POST отправляет данные в теле запроса и используется для создания/изменения/удаления.
2. **PRG.** Post-Redirect-Get: после обработки POST-запроса контроллер делает перенаправление на GET. Это предотвращает повторную отправку формы при обновлении страницы.
3. **`DeleteConfirmed`.** GET-запрос не должен изменять данные. Отдельное POST-действие исключает случайное удаление по ссылке или prefetch-запросом.
4. **Поиск через строку запроса.** Форма отправляет GET-запрос с параметром `search`. Контроллер читает его, фильтрует коллекцию через `Where` и `Contains`, затем передаёт результат в представление.
5. **Текущее значение поиска.** Сохранить его в модели представления или `ViewData["CurrentFilter"]` и подставить в `value` поля ввода.
6. **Без `[ValidateAntiForgeryToken]`.** Форма останется уязвимой к CSRF: злоумышленник может заставить браузер пользователя отправить POST-запрос.
7. **Скрытое поле `Id`.** Оно передаёт идентификатор редактируемой записи, чтобы контроллер знал, какой объект обновлять.
8. **Клиентская и серверная валидация.** Клиентская улучшает UX, но её можно обойти. Серверная (`ModelState.IsValid`) обязательна как защита данных. Нужны обе.
9. **Сортировка по нескольким полям.** Передавать параметр `sortOrder` и в `switch` выбирать `OrderBy`/`OrderByDescending` для нужного столбца, сохраняя направление.
10. **`AsQueryable()`.** Позволяет строить запрос как выражение и выполнять фильтрацию/сортировку/пагинацию на стороне базы, а не в памяти.

## Как проверить

1. Откройте `/Properties/Index`.
2. Проверьте поиск, фильтры, сортировку и переходы по страницам.
3. Откройте объект, нажмите «Изменить», сохраните.
4. Удалите тестовый объект и убедитесь, что он исчез из списка.
5. Отправьте форму с пустым названием — должны появиться сообщения валидации.
