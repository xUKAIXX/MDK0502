# Практическая работа № 7. Аутентификация и авторизация в ASP.NET Core

**Вариант 3:** агентство недвижимости.

**Тема:** ASP.NET Core Identity, роли, клеймы и политика авторизации.

**Цель:** реализовать регистрацию, вход, роли, клеймы и разграничение доступа к объектам и действиям.

## Что сделано

- `ApplicationUser : IdentityUser` с полями `FullName`, `Phone`, `RegisteredAt`;
- `ApplicationDbContext` наследуется от `IdentityDbContext<ApplicationUser>`;
- регистрация и вход через `UserManager` и `SignInManager`;
- роли `Admin`, `Agent`, `Client`;
- клейм `RegisteredAt`, добавляемый при регистрации и в сидере;
- политика `OnlyAdults`: доступ только пользователям, зарегистрированным более года назад;
- страница `/Home/Adults` с политикой;
- страница `/Account/AccessDenied`;
- у объекта есть `OwnerId` и `OwnerName`;
- обычный клиент видит только свои объекты, администратор и агент — все;
- создание/редактирование/удаление объектов доступно только `Admin` и `Agent`;
- изменение статуса объекта — только `Admin`/`Agent`.

## Ответы на контрольные вопросы

1. **Аутентификация и авторизация.** Аутентификация — проверка личности (вход по email и паролю). Авторизация — проверка прав (`[Authorize(Roles = "Admin")]`, политика `OnlyAdults`).
2. **`UserManager<ApplicationUser>`.** API Identity для создания пользователей, хеширования паролей, проверки пароля, управления ролями и клеймами.
3. **Наследование от `IdentityUser`.** Даёт готовые `Id`, `UserName`, `Email`, `PasswordHash`, security stamp и другие поля. Не нужно реализовывать хеширование и хранение заново.
4. **Клейм `RegisteredAt`.** Это утверждение о пользователе. Он позволяет политике проверять дату регистрации прямо по `ClaimsPrincipal`, без обращения к базе.
5. **Роль и политика.** `[Authorize(Roles = "Admin")]` проверяет роль. `[Authorize(Policy = "OnlyAdults")]` проверяет произвольное условие — в нашем случае клейм и дату регистрации.
6. **`DeleteBehavior.SetNull`.** При удалении пользователя его объекты остаются, но `OwnerId` становится `NULL`. Это позволяет не терять объекты.
7. **Почему фильтрация по владельцу.** Для клиента запрос дополняется условием `OwnerId == текущий пользователь`. Администратор и агент это условие не получают и видят все объекты.
8. **Если удалить `AccessDeniedPath`.** Приложение будет использовать стандартный путь `/Account/AccessDenied`. Если ваша страница отказа находится по другому адресу, пользователь увидит стандартную страницу или 404.
9. **Проверка роли.** В представлении — `User.IsInRole("Admin")`, в контроллере — `[Authorize(Roles = "Admin")]` или `User.IsInRole`. Атрибут применяется декларативно до выполнения действия; `IsInRole` — проверка в коде.

## Как проверить

1. Войдите как `admin@agency.local` — доступны все объекты и кнопки управления.
2. Войдите как `client@agency.local` — видны только объекты, созданные этим клиентом.
3. Откройте `/Home/Adults` под клиентом — должно перенаправить на «Доступ запрещён»; под администратором — открыть страницу.
4. Попробуйте открыть `/Properties/Create` под клиентом — доступ запрещён.
