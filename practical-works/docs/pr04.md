# Практическая работа № 4. Модели, DTO и репозитории

**Вариант 3:** агентство недвижимости.

**Тема:** предметная модель, EF Core, DTO, репозитории и разделение слоёв.

**Цель:** спроектировать модель предметной области, отделить сущности хранения от контрактов API, реализовать репозитории и проверить валидацию.

## Что сделано

- слои `Domain`, `Application`, `Infrastructure`, `Web`;
- доменные сущности с бизнес-правилами: `Property`, `PropertyType`, `District`, `Agent`, `Deal`;
- DTO для чтения и записи: `PropertyDto`, `PropertyListItemDto`, `CreatePropertyRequest`, `UpdatePropertyRequest`, `DealDto` и др.;
- репозитории: `PropertyRepository`, `PropertyTypeRepository`, `DistrictRepository`, `AgentRepository`, `DealRepository`;
- сервисы с проверкой ссылочной целостности (тип, район, агент должны существовать);
- валидация на трёх уровнях: атрибуты DTO, бизнес-правила сущностей, ограничения БД;
- конфигурации EF Core в отдельных классах;
- Swagger для Web API.

Ключевые файлы:

- `src/RealEstateAgency.Domain/*.cs`
- `src/RealEstateAgency.Application/Contracts/*.cs`
- `src/RealEstateAgency.Application/Properties/PropertyService.cs`
- `src/RealEstateAgency.Infrastructure/Persistence/Repositories/*.cs`

## Ответы на контрольные вопросы

1. **Сущность и DTO.** Сущность — объект предметной области с идентичностью и бизнес-правилами. DTO — контракт передачи данных, без бизнес-поведения, защищает API от внутренней модели.
2. **Зачем Domain.** Домен содержит бизнес-правила и не зависит от EF Core и ASP.NET. Это делает правила переиспользуемыми и тестируемыми.
3. **Агрегат.** Группа сущностей с общей границей согласованности; транзакция не должна пересекать границу агрегата.
4. **Репозиторий и `IQueryable`.** Если возвращать `IQueryable`, логика запросов расползается по приложению, а репозиторий перестаёт быть абстракцией. Лучше возвращать материализованные списки.
5. **`IEntityTypeConfiguration<T>`.** Выносит настройку EF Core из сущности и из `OnModelCreating`, упрощает поддержку.
6. **Поиск конфигураций.** `modelBuilder.ApplyConfigurationsFromAssembly(typeof(AppDbContext).Assembly);`.
7. **`HasOne/WithMany` и `HasMany/WithMany`.** Первая — связь «один ко многим», вторая — «многие ко многим» через промежуточную таблицу.
8. **`AsNoTracking`.** Отключает отслеживание изменений для read-only запросов, экономит память и время.
9. **Где валидировать.** На границе (атрибуты DTO), в домене (бизнес-правила) и в БД (ограничения). Все уровни дополняют друг друга.
10. **Почему нельзя редактировать миграцию.** Применённая миграция — часть истории схемы; изменение может привести к расхождению модели и базы. Нужно создавать новую миграцию.

## Как проверить

1. Запустите приложение и откройте `/swagger`.
2. Выполните `GET /api/properties` — список объектов.
3. Выполните `POST /api/properties` с корректными и некорректными данными — 201 и 400 соответственно.
4. Проверьте, что при создании объекта с несуществующим агентом возвращается 400 с сообщением.
